**v0.5.0** (2026-07-30) — first stable release on the `0.5.x` line.

Consolidates three minor-beta cycles (`0.4.1` / `0.4.2` / `0.4.3`) of
work since `v0.4.0` into a single stable build. The headline is a
**new multi-model adapter package (`@duya/ai`)** that unifies provider
protocols, plus an **Extensions redesign** that merges plugins,
skills, MCP, and app connections into one entry point, and a
**memory v2** pipeline that persists rollout-derived knowledge with
evidence tracking.

**Headline**

This release ships a standalone `@duya/ai` workspace package that
normalizes Anthropic, OpenAI (including Responses API), MiniMax,
DeepSeek, Qwen, GLM, Kimi, Ollama, and OpenRouter behind one
capability-driven adapter. Model effort options are now filtered by
the current model's capabilities, and per-model compat overrides
survive the full IPC round-trip. The Extensions page replaces three
separate settings entries with a unified interface backed by a
first-party plugin catalog, App Connection OAuth infrastructure, and
a remote MCP connector. Memory v2 replaces the legacy wiki-agent with
a consolidator + recall pipeline that deduplicates, tracks evidence,
and exposes a dedicated memory provider picker.

**Highlights**

- **`@duya/ai` multi-model adapter package (NEW)**
  - Workspace package (`packages/ai/`) with anthropic-messages,
    openai-completions, and openai-responses protocol implementations.
  - think-tag-parser state machine and simple-options helpers for
    reasoning model normalization across vendors.
  - Provider presets for MiniMax (CN/Global dual-protocol), DeepSeek,
    Qwen, GLM, Kimi, Ollama, and OpenRouter.
  - `createAIClient` factory with lazy loading; `findModelCompat`
    resolver for capability-driven effort options and budget
    separation (reasoningBudget vs totalOutputBudget).
  - ParameterDiagnostic three-state diagnostics; DuyaReasoningSettings
    as an effort superset.
  - Upstream provider tracking (OpenRouter `chunk.provider.name`) and
    user compat overrides persisted across IPC.
  - Migrated idle-timeout and prompt-caching utilities from the agent
    layer into `@duya/ai`; added robustness test suites.

- **Extensions redesign + plugin product definition**
  - Merges Plugins, Skills, and MCP settings entries into a single
    Extensions page with four sub-pages and a marketplace modal.
  - Five-element plugin model: MCP/App Connection + Skills + Workflow
    Templates + Permissions + UI; Manifest v2 with
    `components.workflows` and `permissionPolicy`.
  - First-party catalog of 9 plugins (GitHub, Playwright, Figma,
    Supabase, PostgreSQL read-only, Sentry, Vercel, Notion, Linear).
  - App Connection OAuth infrastructure: safeStorage-encrypted token
    vault, loopback PKCE flow, token auto-refresh, single-flight
    dedup, and risk-tier permission gating.
  - Remote MCP connector so App Connections can host MCP servers
    without a local stdio process.
  - Workflow templates with variable substitution and
    `duya:prefill-chat-input` handoff; template launch UI in
    PluginDetailView.

- **Memory v2**
  - Replaces legacy wiki-agent and memory UI with a consolidator +
    recall pipeline (Plan 306).
  - Migration 0005 adds `memory_entries`, `evidence`,
    `usage_events`, and `phase2_runs` tables.
  - Global lock dedup, usage telemetry, and MemoryRecallTool.
  - Dedicated memory provider picker (AppConfig.memoryProviderId)
    with fallback to active provider; LLM client built once at worker
    startup with full compat flags.
  - Consolidator and projectionContent simplified to reduce allocation
    churn; eligibility and lease tightened against double-consolidation.
  - memorySection prompt surfaces consolidated projections with
    evidence references instead of raw rollout excerpts.

- **MCP first-chat tool race fix**
  - Worker readiness now blocks on MCP initialization via a
    `mcpReady` Promise with wait/notify in DuyaAgent, eliminating the
    race where the first chat request processed before MCP tools
    loaded.
  - Hardcoded built-in tool allowlist replaced with a dynamic
    ToolRegistry query so all registered tools are visible without
    list maintenance.

- **Conductor canvas as knowledge workspace**
  - Multi-canvas management tool (list/create/switch/rename) with
    session binding (`chat_sessions.conductor_canvas_id`).
  - Native Document, Table, PDF, and Database elements; Document and
    Canvas rendering modes.
  - Connector geometry controls rebuilt; rich text notes and link
    creation dialog.
  - Passive push-aside collision removed; element overlap is now
    legal, auto-layout moved to toolbar.
  - Canvas tool sizing guidance rewritten for compact tiers.

- **Built-in browser backend**
  - Duya webview as a first-class browser backend alongside the
    Chrome extension; auto/extension/built-in modes with in-toolbar
    toggle, effective on running agents without re-init.
  - Cookie importer reads Chrome/Edge SQLite cookies with DPAPI
    decryption and writes to the `persist:duya-local-browser`
    partition.
  - WebviewCDPClient drives the sidebar `<webview>` via a daemon
    `/webview-command` endpoint.
  - Backend degradation chain with settings UI and 9 unit tests.

- **Code review workspace (Plan 307)**
  - Read-only Code Review panel in the sidebar with unified/split
    diff, context folding, and wrapping.
  - `git:review` and `git:review-diff` IPC bridge with security
    boundary (rejects absolute paths, traversal, `.git` metadata;
    1 MB output cap).
  - Hands off selected files as chat attachments.

- **Turn-review history + prompt refactor (Plan 308)**
  - Each chat turn captures a HEAD→working-tree delta snapshot;
    Code Review panel defaults to the most recent turn.
  - System prompt restructured into composable sections
    (identity/personality/rules/system/workingWithTheUser);
    ToolExecutor.getPrompt() injects tool prompts on demand.
  - Multi-agent collaboration and identity sections added.

- **On-demand tool discovery (Plan 241)**
  - `tool_search` lets the LLM discover specialized tools
    (canvas_*, research_memory:*, etc.) on demand instead of
    carrying 30+ tool definitions in every request.
  - `ExposeMode` (always/discoverable/internal) on ToolMeta;
    StreamChat dynamically injects discovered tools on the next turn.

- **Gateway relay + cron agent profiles**
  - Dedicated agent profiles for gateway (Feishu/WeChat/QQ/Telegram/
    Discord/WhatsApp) and cron automation with tool allowlists.
  - IM platforms gain end-to-end voice/file/video media support.
  - Cron long-delay cap with re-arming; broken schedules isolated
    from the scheduler.

- **Provider robustness**
  - MiniMax: synthesize empty-id tool_use, highspeed variant
    `max_tokens` cap, skip data: URLs, flatten BrowserTool anyOf,
    drop empty tool_call_id; safety-filter errors (HTTP 500
    `input new_sensitive (1026)`) no longer retried.
  - `initAgent` guards against null providerConfig with an actionable
    error instead of a 30s timeout.
  - macOS uses `vm_stat` for accurate available memory; memory
    rejection threshold raised from 0.95 to 0.98.
  - Strict `tool_use`/`tool_result` ordering restored and persisted.

- **macOS packaging**
  - Native macOS builds (Apple Silicon priority); native module
    architecture validation for `better-sqlite3` and `node-pty`.
  - Two-pass build breaks the `@duya/agent`↔`@duya/conductor` type
    dependency cycle.
  - macOS app menu, tray icon, system proxy detection, and
    Homebrew/nvm node path probing.

- **UI and i18n**
  - All frontend icons unified to `@tabler/icons-react` (stroke 1.25).
  - Unified settings card style (`rounded-lg border bg-[var(--surface)]
    p-4`) with divider/footer negative-margin positioning.
  - Sidebar project priority/manual sort and by-project grouping.
  - Chat column min-width 420px; inline streaming thinking preview;
    markdown table column-width guard for inline code.
  - README redesigned with project-native visual system.

**Breaking changes**

No Conventional-Commits `BREAKING CHANGE` footers, but users may
notice:

- Legacy wiki-agent and old memory UI removed; replaced by memory v2.
- Conductor passive push-aside collision removed; overlap is now
  legal, auto-layout is a toolbar action.
- Widget iframe CSP drops `duya-file:`; widget authors must use
  https/data URLs.
- Unused tools removed (WebFetch, WebSearch, EnterWorktree,
  ExitWorktree, WorktreeContext, ListMcpResources, ReadMcpResource,
  TeamCreate, TeamDelete).
- Research mode rewritten as a Modifier paradigm; old Orchestrator
  and SSEProtocol types removed from the public barrel.
