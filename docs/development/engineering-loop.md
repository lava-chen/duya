# 长程开发与接续

根 AGENTS 规定必须保存的状态；本指南说明如何把一次任务分成可接续的回合。

## 每轮执行

1. 读取同一计划的验收、依赖和接续记录，再对账 Git、PR 与已有副作用。
2. 每个 agent 在自己的独立 worktree 选择切片，确定路径所有权、base 与验收；文档和小改也按 [worktree 全流程](worktree.md)执行。
3. 实现后验证受影响的生产链路；记录实际结果，失败留在当前切片处理。
4. 停下前更新[计划模板](../exec-plans/template.md)中的进度、证据与下一步，避免另起 handoff 复制状态。

## 分工

| 职责 | 产出 |
| --- | --- |
| 规划 | 切片边界、依赖、路径所有权和可判定验收 |
| 实现 | 自己检出的改动、commit / diff、具名验证结果 |
| 评估 | 基于实际输出的判断；失败给复现步骤 |
| 集成 | review、CI、集成顺序与合并后验证 |

小任务可由一个会话承担，仍必须独立 worktree 与 PR；共享文件指定一个 owner，高风险改动独立评估。

## 接续与关闭

新会话先核对成果仍然存在，尤其是未提交路径和已经发生的迁移、发布或合并，再执行下一条动作。
任务完成需满足验收并说明已实现、已验证、已合并的范围；所有变更通过 PR；未经授权不合并，集成任务在合并后验证前不关闭，等待期间保留检出与接续记录。
归档见[计划入口](../exec-plans/README.md)。

这些开发约束不证明产品已经实现自动认领、lease、journal 或恢复执行。
