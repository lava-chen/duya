# 文档维护约定

适用于 `docs/`。根规则继续有效；目录职责见 [README.md](README.md)。

## 写作

- 开头直接写用途或结论；每段回答一个问题，每条规则给出条件和动作。
- 规则写约束，流程写步骤，计划写进度，设计写理由；同一事实只在一个位置维护，其他地方链接。
- 常驻入口只留跨任务约束与导航；命令细节、排障和事故经过放专题文档。
- 用“已实现 / 已验证 / 已合并 / 待验证”描述状态；测量写日期、SHA、环境与范围。
- 避免口号、重复警告、对话回放和没有适用条件的“永远”。关键风险用一条规则加安全路径。
- 信息不足就写待核对和核对动作，不用旧数字或文件存在代替现状证明。

## 文件与归属

- 新主题使用简短 `kebab-case.md`；计划使用 `YYYY-MM-DD-topic.md`，已有编号保持不变。
- 多文件主题才建子目录；入口解释读哪一份，不罗列所有文件。不要为一次会话新建顶级分类。
- 新目录在文档地图中说明职责，并核对 `.gitignore`；不要只在本机留下必需文件。
- 原始调查报告与截图放 `docs-local/research/<topic>/`；版本化 references 只保留提炼后的依据与结论，不在 docs 根目录按调查对象建目录。
- 恢复材料的来源与契约并入所属执行计划；旧源码留 Git 历史或本地档案，不另建 recovered 目录，不当作生产实现。
- 不复制另一份 AGENTS/CLAUDE 规则；需要特定客户端适配时只引用权威入口。

## 长程任务

- 先查[计划入口](exec-plans/README.md)和[完整目录](exec-plans/catalog.md)，复用已有计划。
- 新计划使用[模板](exec-plans/template.md)。保留目标、边界、验收、进度、关键决策和接续点。
- 文档修改同样先进入本 agent 的独立 worktree，经过验证与 PR 交付；不得直接写共享检出或直推主分支。
- 多 agent 派工记录路径所有权、依赖和集成顺序；每个 agent 各占一个检出。
- 每次停下更新证据与下一步；完成计划进入 `archive/`，不得因归档丢失可复现结论。
- 不批量改写历史计划或把未重新验收的任务标为完成。旧状态矛盾在本任务接续点注明。

## 交付检查

- Markdown 链接使用相对路径，目标须为 Git 已跟踪或本次待加入且未被忽略的文件。
- 当前入口不得依赖 `docs-local/`、个人绝对路径、已删除文件或会话上下文。
- 移动前查入链，移动后更新链接；历史路径不能直接修复时保留明确的兼容指针。
- 文档整理检查链接、Git 可见性、编码和 diff；涉及代码行为时另跑根规则要求的门禁。
- 精简参考：[写作依据](development/documentation-style.md)。篇幅以读者能完成操作为准。
